# Laravel-to-Go cutover and publication

Go is not yet the production backend. Repository hardening does not perform a deployment or rotate live credentials. The operator owns the maintenance window and receiver rewiring.

1. Take and verify a recoverable database backup. Rehearse the migration on an isolated database copy with outbound notification delivery disabled. Follow database-migration.md; review timestamp semantics in 012 and resolve any duplicate upstream IDs or purchase ownership conflicts explicitly. Stop Laravel writers, jobs, importers and queue workers during schema cutover. Do not run both sets of notification workers on the same workload.
2. Set a new random JWT secret and explicit administrator bootstrap credentials if needed. Review existing admin_users rows and reset/remove any unwanted historical seeded administrator. Configure production SMTP, provider app audiences, webhook sender/signing credentials, subscription products and environments, trusted proxy CIDRs, and application base URL. New Go tokens deliberately invalidate old token formats.
3. Run `cmd/migrate` alone with the intended migration-role connection. It does not start receivers, importers, or notifications. Migration errors roll back that file and stop; do not mark failed versions as applied manually. **Migration 029 changes the IAP ownership ledger and the two store-ID indexes; deploy the matching server binary before serving `/iap/*`, webhooks, or backfill.** A pre-029 binary's `ON CONFLICT` target (`platform, original_transaction_id`) no longer exists once 029 is applied, so its validate/restore/webhook claims fail with `42P10` until redeployed. Run `cmd/adapty-backfill` only after 029 is applied; it is now idempotent and upserts the ledger link.
4. Provision/approve each receiver and generate replacement credentials. Five receiver credentials were embedded in earlier private commits; none may be reused at cutover or after publication. Rotate the one still used by the old path and retire all others wherever accepted. Replace receiver configuration with the authenticated Go endpoint and new key. The old UUID/Sanctum routes and legacy receiver mode do not exist in the new server.
5. Start the Go deployment, then switch receivers and application clients. Verify approved receiver connections, decoded message storage, fan-out, one legitimate notification on a controlled test account, login/logout/recovery, subscription validation/restore and signed webhook delivery. Production-sized migration duration, radio hardware and real provider delivery require deployment rehearsal; unit tests are not substitutes for those checks.
6. Have a rollback plan that includes schema compatibility and data written after cutover. Restore from a verified backup only through the operator's reviewed procedure. Never point an old application at a partially migrated database without checking compatibility.

Before making a repository public:

- Verify all embedded historical credentials have been retired. Review any prior images/binaries because SQL migrations were embedded in the server binary.
- Publish a reviewed clean import, or deliberately sanitize all refs/history being published. This work preserves the private original history as requested; earlier commits still contain old keys, operational notes, and the previous FSL license. A new commit does not erase them. Review existing copies, releases, CI artifacts and remote refs separately.
- Export tracked reviewed files only. Local ignored legacy projects, credentials, `.env` files and pager logs must not be included in a directory ZIP.
- Run the current-tree secret scan, dependency audits, fresh-checkout build and disposable-database tests. Configure secret scanning/push protection and restrict release/tag/workflow permissions.
- Review third-party asset provenance and notices. New project code is AGPL-3.0-only; original third-party licenses and already-granted historical rights remain applicable.
- Configure a working private security contact and source-code link for the actual deployment. Modified hosted versions must provide the source offer required by AGPL section 13. Keep the repository URL available in the website/app About information.
