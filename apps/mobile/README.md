# RFSPager — Mobile

The iOS + Android RFSPager app: a community pager feed for NSW emergency
services (not affiliated with any agency). Part of the
[RFSPager monorepo](../../README.md).

- **Framework:** Expo SDK 57 / React Native 0.86 / React 19.2
- **Navigation:** Expo Router with `expo-router/unstable-native-tabs`
- **State:** Zustand (`src/stores`)
- **Data:** TanStack Query over REST (`src/services/api-client.ts`)
- **Push:** Firebase Messaging + Notifee
- **IAP:** `expo-iap` with server-side Apple JWS validation
- **Bundle ID:** `io.devlan.rfspager` (iOS + Android)

For architecture notes and conventions see [`CLAUDE.md`](./CLAUDE.md).

---

## Quickstart

```bash
pnpm install --frozen-lockfile

# 1. Build a dev client (once per native-dep change). Pick one:
eas build --profile development --platform ios
eas build --profile development --platform android
#   …or for the iOS simulator:
eas build --profile preview   --platform ios --local

# 2. Install the dev client on your device / simulator, then:
pnpm dev
```

Copy `.env.example` to your ignored `.env` and set `EXPO_PUBLIC_API_URL` to your
own API. Set the same variables in the appropriate EAS build environment; profiles
no longer embed production hosts or provider project IDs. For physical devices,
use a reachable development server. Loopback is the default, and a release build
must explicitly configure its API and EAS project.

Use Xcode 26.6 on macOS 26 for the release workflow. SDK 57 supplies the native
Android SDK defaults; do not restore older SDK or disabled-new-architecture overrides.
Firebase native builds require your own platform configuration files. See the root
README and `app.config.js` for Maps, Facebook, EAS and team environment variables.
Client identifiers are not server secrets, but must be restricted to your own app.

## Builds & releases

Releases are built by the `mobile-release.yml` workflow (manual dispatch with
a `vX.Y.Z` tag) on a GitHub-hosted macOS runner, uploaded to TestFlight and the
Play internal track, then submitted with `scripts/submit-to-stores.sh`. The
full procedure is [`docs/mobile-releases.md`](../../docs/mobile-releases.md);
the credentials CI needs are in [`docs/ci-secrets.md`](../../docs/ci-secrets.md).

For ad-hoc local builds:

```bash
# Simulator (no signing needed)
eas build --platform ios --profile preview --local

# Release IPA, ready for App Store submission
eas build --platform ios --profile release --local
eas submit --platform ios --profile release --path build-*.ipa

# Release AAB
eas build --platform android --profile release --local
eas submit --platform android --profile release --path build-*.aab
```

## Notes

- The `ios/` and `android/` folders are generated by `expo prebuild` and are
  **git-ignored**. Don't hand-edit them — model native-side changes via
  `app.config.js` / `app.base.json` plugins or `expo-build-properties`.
- `react-native-worklets@^0.8` is a peer dependency of
  `react-native-reanimated@4.x`. Don't remove it.
- Firebase pods need `useFrameworks: "static"` + `forceStaticLinking` (set
  in `app.json`).
